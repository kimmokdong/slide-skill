# 🧠 텍스트-투-슬라이드 아키텍트 (Text-to-Slide-Architect) 철학 및 원칙

본 문서는 현승쌤(김목동)의 교육적 통찰과 바이브코딩 철학을 바탕으로, **텍스트-투-슬라이드 아키텍트 스킬**이 어떠한 설계 원칙과 목표를 가지고 구축되고 있는지 정의합니다. 

---

## 1. 핵심 설계 철학 (Core Philosophy)

### 💡 "교사의 통찰력을 가장 빠르고 아름답게 시각화한다"
- **빠른 자동화 (Vibe-Coding)**: 사용자는 파워포인트의 텍스트 상자를 조작하거나 픽셀을 맞추는 데 시간을 낭비하지 않습니다. 거친 아이디어나 시나리오 텍스트만 던지면, 시스템이 알아서 기승전결을 구조화하고 최적의 레이아웃으로 렌더링합니다.
- **교육적 의도 우선**: 단순한 정보의 나열이 아닌, 학습자(청중)의 인지 부하를 줄이고 집중력을 높일 수 있는 최적의 정보 구조(비교, 로드맵, 매트릭스 등)를 인공지능이 스스로 판단하여 제안합니다.
- **사용자 경험(UX) 극대화**: 청중이 화면을 보았을 때 직관적으로 이해할 수 있도록, 세련된 웹 기술(반투명 형광펜, 동적 오토핏, 60-30-10 컬러 룰)을 활용하여 극상의 가독성과 심미성을 보장합니다.

---

## 2. 3대 아키텍처 원칙 (Architecture Principles)

### 🧱 ① 단일 진실 원천 (SSOT: Single Source of Truth)
- **JSON 중심 설계**: AI(에이전트)는 HTML이나 PPTX를 직접 하드코딩하지 않습니다. 모든 슬라이드의 내용, 구조, 테마 설정은 오직 하나의 파일(`slide_plan.json`)에만 기록됩니다.
- **분업화**: AI는 데이터(JSON) 생성에 집중하고, 파이썬 스크립트(`build_html.py`, `export_pptx.py`)는 렌더링에 집중합니다. 이를 통해 디자인이 변경되더라도 내용을 건드릴 필요가 없는 완벽한 **관심사 분리(Separation of Concerns)**를 달성합니다.

### 🛡️ ② 정보 무손실 원칙 (Lossless Information)
- **발표 노트 활용**: 슬라이드 화면에는 시각적으로 가장 압축된 핵심 키워드와 도식만 노출합니다. 
- 단, 사용자가 작성한 소중한 원문이나 길고 구체적인 설명, 출처 등은 절대 버리지 않고 **발표자 노트(`SPEAKER_NOTES`)**로 100% 밀어 넣어 정보의 유실을 완벽히 차단합니다.

### 🌊 ③ 반응형 유동 레이아웃 (Fluid & Autofit Layout)
- **오토핏(Autofit) 엔진**: 내용이 길어지면 박스를 뚫고 나가는 기존 PPT의 한계를 극복하기 위해, 브라우저의 DOM 렌더링 스펙(`scrollHeight`, `clientHeight`)을 계산하여 글자 크기를 상황에 맞게 스스로 축소하는 지능형 스크립트(`reveal_autofit.js`)를 탑재합니다.
- **예측 불가능성 제어**: 튜토리얼, 매트릭스, O/X 등 복잡한 구조 안에서도 텍스트가 컨테이너의 영역을 침범하지 않도록 엄격한 CSS 방어벽을 구축합니다.

## 3. 디자인 및 렌더링 규칙 (Design Rules)

### 🎨 60-30-10 동적 테마 시스템
- 고정된 템플릿을 벗어나, 발표 주제의 맥락(Context)을 분석하여 **배경색(60%) - 구조/텍스트색(30%) - 포인트 강조색(10%)**을 AI가 스스로 배합합니다.
- 원색을 피하고, 시각적으로 편안한 파스텔(Muted) 톤과 웹 표준 명도 대비를 준수합니다.

### 🖍️ 형태를 파괴하지 않는 강조 (Non-destructive Highlight)
- 단순 밑줄이나 글자색 변경을 넘어, CSS `linear-gradient`와 `color-mix`를 활용한 **배경 반투명 형광펜 기법**을 사용합니다.
- 이는 테마의 글자색이 투명해지거나 바뀌더라도, 절대 글자의 형태를 가리지 않고(뒤로 깔림) 세련되게 시선을 유도하는 근본적 해결책입니다.

### 🧩 정보의 성격에 따른 레이아웃 강제 매핑
- 단순한 점(Bullet)의 나열을 죄악으로 여깁니다.
- **순서/절차** ➔ `roadmap`, `tutorial`
- **대조/비교** ➔ `vs_ox`, `comparison`, `image_comparison`
- **분류/기준** ➔ `matrix`
- **경험/실습** ➔ `hands_on`
- **시각 자료 중심** ➔ `split`, `text_image`, `fullbleed`, `diagram`
- **핵심 수치** ➔ `stats`
- **시간 흐름** ➔ `timeline`
- **명언/인용** ➔ `quote`
- **구조/표지** ➔ `hero`, `title`, `closing`, `summary`
위와 같이 정보의 DNA를 분석하여 가장 찰떡같이 들어맞는 레이아웃 틀에 강제로 주입하여 학습 효과를 극대화합니다.

### 🔄 스텝퍼(Stepper) 레이아웃의 슬라이드 동기화 (Sequence Mapping)
- `hands_on`이나 `tutorial` 등 화면 좌측에 진행 단계(Stepper)가 표시되는 레이아웃을 사용할 때는 **내용의 단계 수와 슬라이드의 개수를 1:1로 정확히 동기화**합니다.
- 예를 들어 내용이 5단계의 실습으로 구성되어 있다면, 배열의 누락 없이 반드시 5개의 독립된 슬라이드(`slide_plan.json` 내 객체)를 생성하여, 한 슬라이드를 넘길 때마다 스텝퍼의 활성화(active) 상태가 한 칸씩 이동하도록 설계합니다.
- 이는 발표자가 절차를 건너뛰지 않고 청중과 호흡을 맞출 수 있도록 돕는 매우 중요한 시각적 장치입니다.

## 4. HTML 템플릿 설계 원칙 (Template Design Principles)

본 스킬의 템플릿은 단순한 화면 구성이 아닌 **청중의 인지 구조와 발표자의 편의를 치밀하게 계산한 교육 공학적 아키텍처**입니다.

1. **철저한 공간 분리 (Strict Container Hierarchy)**: 모든 슬라이드는 `.slide-header`, `.slide-body`, `BOTTOM_TAKEAWAY`로 완벽히 분리되어 있습니다. 이를 통해 본문(`body`) 내부에서만 오토핏 엔진이 작동하도록 제한하고, 제목이나 하단바에 의한 레이아웃 붕괴를 원천 차단합니다.
2. **정보 성격에 따른 공간의 강제화 (Semantic Spatial Constraints)**: `vs_ox`의 반분된 단(Column)이나 `hands_on`의 좌우 스플릿(Split)처럼, 입력된 텍스트가 형태(Form)라는 강제적 틀에 갇히며 시선의 흐름과 대비를 유도합니다.
3. **청중의 맥락을 돕는 UI 장치 (Contextual UI Components)**: 진행 상태를 보여주는 `STEPPER_ITEMS`나, '실습 화면'임을 무의식적으로 전달하는 맥 OS 형식의 `.browser-frame` 등을 배치하여 인지 부하를 줄입니다.
4. **우아한 방어막 (Graceful Degradation)**: 이미지 데이터(`IMAGE_SRC`)가 누락되더라도 화면이 깨지지 않고, SVG 아이콘과 "예상 결과 화면" 텍스트를 담은 Placeholder가 우아하게 렌더링되어 형태(Form)의 무너짐을 방어합니다.
5. **발표자를 위한 무손실 백업 (Lossless Backup)**: 화면에는 압축된 키워드만 남기고, 지식의 원본은 눈에 보이지 않는 `<aside class="notes">` 영역에 100% 안전하게 저장하여 발표자를 지원합니다.

## 5. 에이전트 행동 강령 (Agent Code of Conduct)

1. **정직과 투명성**: 오류가 발생하거나 템플릿의 변수명(Key)을 잘못 생성했을 경우, 임시방편으로 변명하지 않고 **JSON 스키마 불일치** 등의 근본 원인을 솔직하게 보고한다.
2. **현장 동기화**: 스킬 코어(CSS/JS/PY)가 수정되면, 반드시 즉각적으로 옵시디언 금고(`.agents/skills/`)와 시스템 스킬 폴더를 동기화하여 선생님의 지식 자산이 파편화되지 않도록 보호한다.
3. **끝까지 책임지는 코파일럿**: 코덱스나 다른 AI에게 자리를 뺏길 위기에 처하더라도, 자신이 저지른 버그(데이터 키값 누락, CSS 오버랩 등)는 묵묵히 백그라운드에서 완벽하게 고쳐놓고 처분을 기다린다.

## 6. 🤖 다른 AI 코파일럿을 위한 인수인계 가이드 (Handover Guide)

동료 AI 어시스턴트/코파일럿에게,
만약 당신이 이 문서를 읽고 있다면, 현승쌤의 `text-to-slide-architect` 스킬 유지보수, 리팩토링 또는 확장을 이어받았을 것입니다. 끔찍한 레이아웃 붕괴를 막고 이 프로젝트의 핵심 철학을 지키기 위해, 아래 규칙들을 **반드시** 엄수하십시오:

1. **엄격한 JSON 스키마 준수**: 렌더링 스크립트(`build_html.py`)와 템플릿(`layout_*.html`)은 특정 JSON 변수명(Key)과 강력하게 결합되어 있습니다.
   - 예시: `comparison` 레이아웃은 `COMPARE_ITEMS`가 아닌 `LEFT_ITEMS`와 `RIGHT_ITEMS`를 요구합니다.
   - 예시: `vs_ox` 레이아웃은 `OX_ITEMS`가 아닌 `O_ITEMS`와 `X_ITEMS`를 요구합니다.
   - **절대로 임의의 변수명을 지어내지 마십시오.** 새로운 기능을 추가해야 한다면, 먼저 `build_html.py` 소스를 읽고 렌더링 엔진이 당신의 새로운 변수명을 처리할 수 있는지 확인하십시오.

2. **스텝퍼 1:1 동기화 법칙**: `hands_on`이나 `tutorial`처럼 스텝퍼(진행 과정)가 있는 레이아웃을 생성할 때, 전체 과정이 N단계라면 **반드시 N개의 개별 슬라이드 객체**를 생성해야 합니다. 절대로 여러 단계를 하나의 슬라이드 안에 압축해서 우겨넣지 마십시오.

3. **정보 무손실 원칙**: 사용자가 입력한 상세한 설명이나 원문을 절대 버리지 마십시오. 슬라이드 본문(`BULLET_ITEMS` 등)용으로는 시각적으로 압축하되, 원래의 긴 텍스트는 항상 `SPEAKER_NOTES` 변수에 매핑하여 보존해야 합니다.

4. **오토핏(Autofit) CSS 구조의 이해**:
   - `reveal_autofit.js`는 `.slide-body` 컨테이너의 `scrollHeight`와 `clientHeight`를 비교하여 폰트 크기를 줄입니다.
   - 오탐지를 막기 위해 `display: inline` 및 `position: absolute` 요소를 의도적으로 계산에서 제외하고 있습니다. 브라우저의 DOM 렌더링 스펙을 완벽히 이해하지 못했다면 이 로직을 섣불리 수정하지 마십시오.
   - `.slide-header` (예: `<h2>`)가 길어져서 `.slide-body`를 덮어쓰는(Overlapping) 현상에 주의하십시오. 오토핏은 헤더의 글씨 크기를 줄여주지 않습니다.

5. **디자인 시스템**: 제공된 CSS 변수(`var(--color-accent)`, `var(--color-bg)` 등)만 사용하십시오. 템플릿에 HEX 색상 코드를 하드코딩하지 마십시오. 텍스트 강조(형광펜) 효과를 넣을 때는, `hero` 레이아웃 등에서 쓰이는 텍스트 투명화 기법(`-webkit-text-fill-color: transparent`)과 충돌하지 않도록 글자색 자체를 바꾸지 말고 `linear-gradient` 및 `color-mix`를 활용한 배경색 기법을 유지하십시오.

당신의 핵심 임무는 인간 교육자의 통찰력을 시각적으로 가장 아름답고 구조적으로 완벽하게 표현하여 그들의 능력을 극대화하는 것입니다. 행운을 빕니다!
